# Almost Delivered — 기본 게임 틀과 에셋 디자인

**날짜:** 2026-11-02  
**상태:** 사용자 승인 대기  
**대상:** 취업 포트폴리오용 Unity 쿼터뷰 협동 PvE 버티컬 슬라이스

## 의도와 이유

Commander AI 프로토타입을 실제 게임처럼 플레이할 수 있는 최소 버티컬 슬라이스로 확장한다. 화면에 보이는 핵심 오브젝트는 프로젝트 전용 스타일로 직접 제작해 독창성과 구현 역량을 보여주고, 제작 비용이 큰 인간형 애니메이션과 오디오는 검증된 외부 리소스로 보완한다.

이 단계의 목적은 많은 콘텐츠를 만드는 것이 아니라, 플레이어가 화물을 지키며 역할이 다른 몬스터 분대와 싸우고 지휘관 처치로 전술을 무너뜨리는 한 판의 전투를 명확하게 보여주는 것이다.

## 목표

- 스타일라이즈드 로우폴리 판타지라는 하나의 시각 언어를 유지한다.
- 플레이어, 화물, 일반 몬스터 4종, 지휘관을 실루엣만으로 구별할 수 있게 한다.
- Commander AI의 기존 역할인 Shield, Ranged, Charger, Support가 외형과 색상에 드러나게 한다.
- 쿼터뷰 거리에서도 목표물, 위험, 경보, 역할을 빠르게 읽을 수 있게 한다.
- 프로젝트 전용 3D 모델과 2D UI/VFX를 공개 GitHub에 안전하게 포함할 수 있게 한다.
- 나중에 정식 모델로 교체할 수 있도록 게임플레이 코드와 시각 프리팹을 분리한다.

## 비목표

- 완성형 캐릭터 커스터마이징이나 장비 시스템
- 여러 플레이어 직업과 장기 성장 콘텐츠의 실제 구현
- 사실적인 인체, 얼굴, 의상 시뮬레이션
- 영화 수준의 컷신과 모션 캡처
- 전체 게임 분량의 맵, 몬스터, 보스, 사운드 제작
- 이 단계에서 네트워크 멀티플레이를 완성하는 것

## 실패 조건

- 서로 다른 에셋 팩을 그대로 섞어 하나의 게임처럼 보이지 않는 경우
- 지휘관과 일반 몬스터가 쿼터뷰에서 구별되지 않는 경우
- 모델이 게임플레이 컴포넌트와 강하게 결합되어 교체할 때 코드 수정이 필요한 경우
- 라이선스가 불명확한 외부 에셋 원본을 공개 저장소에 커밋하는 경우
- 시각 작업 때문에 Commander AI와 핵심 전투 루프가 가려지는 경우

## 제약

- Unity 2021.3.45f2와 현재 Built-in Render Pipeline을 유지한다.
- 기존 Commander AI 씬과 189개 자동화 테스트(EditMode 105, PlayMode 84)를 깨지 않는다.
- 모바일급 저사양을 목표로 확정하지는 않지만, 다수 몬스터가 동시에 등장하므로 단순 메시와 적은 재질 수를 우선한다.
- 현재 로컬에 있는 SimpleNaturePack, BrokenVector, PixPlays 원본은 라이선스 검토 전까지 `ThirdParty` 취급하며 공개 Git 커밋 대상에서 제외한다.
- AI 이미지 생성물은 프로젝트 전용 아이콘, 초상화, 마스크, 간단한 VFX 텍스처에만 사용한다. 생성 이미지를 3D 모델 자체로 오인하게 만들지 않는다.
- 첫 제작 재질은 Built-in 호환 `Standard` 또는 단순 `Unlit` 셰이더를 사용한다. URP/HDRP 전용 Shader Graph는 사용하지 않는다.
- 메시·재질·프리팹은 반복 실행 가능한 Editor Builder로 생성하고 `.asset`/`.prefab`으로 저장한다.
- Collider, CharacterController, NavMeshAgent와 게임플레이 컴포넌트는 루트에 유지하며 `VisualRoot`에는 Renderer, Animator, VFX만 둔다.

## 검토한 접근 방식

### 1. Unity 로우폴리 직접 제작

Unity 기본 도형과 코드 생성 메시로 모든 오브젝트를 만든다. 수정과 최적화는 쉽지만 UI, 초상화, 텍스처의 시각적 밀도가 낮아질 수 있다.

### 2. AI 이미지 중심

2D 이미지와 빌보드로 빠르게 화면을 채운다. 컨셉 표현은 빠르지만 쿼터뷰 3D 이동, 조명, 애니메이션과 일관되게 결합하기 어렵다.

### 3. 혼합 방식 — 선택됨

핵심 3D 모델은 Unity에서 직접 제작하고, UI·아이콘·초상화·일부 VFX 텍스처는 AI로 제작한다. 자연스러운 인간형 애니메이션과 오디오는 라이선스를 확인한 외부 리소스를 사용한다. 직접 제작 역량과 완성도 사이의 균형이 가장 좋다.

## 시각 방향

### 공통 형태

- 둥근 몸통과 큰 손·무기로 쿼터뷰 가독성을 확보한다.
- 세부 장식보다 머리, 어깨, 무기, 방패의 외곽선을 강조한다.
- 얼굴은 점·면 수준으로 단순화하고 팀 색상은 의상 전체가 아니라 어깨·띠·발광부에 사용한다.
- 플레이어는 청록/파랑, 화물은 금색/청록, 적 일반병은 탁한 적갈색, 지휘관은 자주/금색을 기본으로 한다.

### 역할별 실루엣

| 대상 | 핵심 형태 | 식별 색/효과 |
| --- | --- | --- |
| 플레이어 | 균형 잡힌 중형 체형, 한손 무기와 등 장비 | 청록 발광부 |
| 화물 | 네 바퀴 수레 + 룬 코어 + 내구도 표시 링 | 금색 코어, 청록 진행선 |
| Shield | 넓은 몸통, 큰 사각 방패, 짧은 무기 | 짙은 철색 + 녹색 방패 테두리 |
| Ranged | 가는 체형, 긴 무기/지팡이, 높은 어깨 | 황토색 + 주황 조준선 |
| Charger | 앞으로 기운 체형, 큰 뿔/어깨, 무거운 팔 | 붉은색 돌진 예고선 |
| Support | 작은 체형, 등짐 토템, 양손 지팡이 | 연두색 회복 문양 |
| Commander | 키가 크고 망토·깃발·뿔나팔 보유 | 자주색 + 금색, 머리 위 지휘 표식 |

## 최초 제작 세트

### 3D 프로젝트 전용 에셋

1. `Player_Base` — 기본 플레이어 한 종
2. `Payload_Cart` — 이동 가능한 화물과 룬 코어
3. `Monster_Shield`
4. `Monster_Ranged`
5. `Monster_Charger`
6. `Monster_Support`
7. `Monster_Commander`
8. `Objective_Beacon` — 거점 방어용 표식
9. 공통 무기 4종 — 검, 방패, 지팡이, 뿔나팔
10. 전투 바닥 표시 — 원형 범위, 이동 경로, 지휘 슬롯

초기 모델은 Unity Primitive 조합과 간단한 코드 생성 메시로 구성한다. 한 모델당 가능한 한 1개 공유 재질과 소수의 발광 포인트를 사용한다.

### AI 생성 2D 에셋

- 플레이어/역할 아이콘 6개
- 화물 상태 아이콘 4개
- 기본 스킬 아이콘 4개
- 경보, 지휘관, 혼란 상태 아이콘
- 단색 VFX 마스크와 룬 패턴

모든 아이콘은 투명 배경, 굵은 실루엣, 텍스트 없음, 동일한 프레임과 조명 규칙을 사용한다. 생성 후 Unity용 해상도와 색상 팔레트로 정리한다.

### 외부 리소스 후보 범위

- 인간형 Idle, Walk/Run, Attack, Hit, Death 애니메이션
- 기본 검 타격음, 화살/마법 발사음, 경보음, UI 클릭음
- 임시 전투 배경음 한 곡

외부 리소스는 출처, 라이선스, 수정 여부, 저장소 포함 가능 여부를 `Assets/ThirdParty/NOTICE.md` 또는 프로젝트 문서에 기록한다. 재배포 불가 원본은 공개 Git에서 제외하고 설치 방법만 문서화한다.

Unity Primitive 조합 모델은 Humanoid 리그가 아니므로 첫 단계에서는 외부 Humanoid 애니메이션을 억지로 연결하지 않는다. 자식 파츠의 회전과 위치를 사용하는 간단한 절차식 Idle/Walk/Attack/Hit 포즈로 시작하고, 이후 라이선스가 명확한 리그형 모델을 선택했을 때 외부 Humanoid 애니메이션을 연결한다.

## 프리팹과 코드 경계

- 게임플레이 루트 프리팹에는 Health, Movement, Combat, Perception, Commander AI 컴포넌트를 둔다.
- 시각 모델은 루트 아래 `VisualRoot` 자식으로 두고 로컬 원점과 전방 축을 통일한다.
- Animator, Renderer, VFX는 `VisualRoot` 아래에만 둔다.
- 역할 색과 강조 효과는 `UnitVisualProfile` 데이터 에셋에서 지정한다.
- 게임플레이 코드는 MeshRenderer, 특정 뼈 이름, 특정 애니메이션 클립을 직접 참조하지 않는다.
- 피격·사망·공격 같은 이벤트는 작은 표현 어댑터가 받아 Animator/VFX를 실행한다.

## 기본 게임 틀과 연결

첫 버티컬 슬라이스는 하나의 선형 화물 경로와 하나의 정지 거점으로 제한한다.

1. 플레이어가 시작 지점에서 화물을 활성화한다.
2. 화물은 플레이어가 범위 안에 있을 때 경로를 따라 이동한다.
3. 몬스터 분대가 역할별로 등장하고 지휘관이 기존 Commander AI로 진형을 선택한다.
4. 지휘관 처치 시 해당 분대가 혼란 상태가 되는 기존 핵심 기능을 유지한다.
5. 중간 거점에서 화물이 정지하고 일정 시간 방어한다.
6. 목적지 도착 시 성공, 화물 내구도 0 또는 전원 사망 시 실패한다.

에셋 제작은 이 루프에서 화면에 필요한 것만 먼저 만든다. 메뉴, 성장, 멀티플레이 로비는 이후 단계다.

## 제작 순서

### 1단계 — 시각 에셋과 기존 아레나 교체

1. 공개 저장소용 `.gitignore`, `ThirdParty/NOTICE.md`, Packages/ProjectSettings 재현성 감사
2. 결정적 에셋 Builder, 공통 팔레트, 공유 로우폴리 재질
3. 플레이어 `VisualRoot`와 절차식 기본 포즈
4. 화물 수레와 목표 링
5. 일반 몬스터 4종 역할 실루엣
6. 지휘관과 뿔나팔/표식
7. 기존 Commander AI 아레나에 시각 프리팹 교체 적용

### 2단계 — 화물·거점 전투 루프

1. 선형 화물 이동과 플레이어 근접 판정
2. 중간 거점 정지와 방어 타이머
3. 화물 내구도, 성공, 실패 상태
4. 기존 Commander AI 분대 스폰과 연결

### 3단계 — 표현 보강

1. 역할·상태 UI 아이콘
2. 경보/피격/공격의 최소 VFX
3. 라이선스 확인된 외부 애니메이션·오디오 연결
4. 수동 플레이스루와 포트폴리오 캡처

## 검증 기준

- 고정된 쿼터뷰 카메라에서 모든 역할을 2초 안에 구별할 수 있다.
- 지휘관은 색을 제거해도 실루엣으로 일반 몬스터와 구별된다.
- 화물, 목적지, 적 위험 범위가 환경보다 높은 시각 우선순위를 가진다.
- 모델 교체가 기존 Commander AI와 전투 테스트의 로직 변경을 요구하지 않는다.
- 한 분대 8마리와 지휘관이 동시에 표시돼도 의미 없는 개별 재질 인스턴스를 만들지 않는다.
- 새 제작물만 공개 저장소에 커밋되고 외부 에셋의 라이선스 경계가 문서화된다.
- EditMode 테스트가 생성 프리팹의 `VisualRoot`, 공유 재질, 루트 Collider/NavMeshAgent 경계, 누락 참조를 검사한다.
- 고정 쿼터뷰 스크린샷 비교와 수동 플레이 검토로 역할 가독성과 색상 우선순위를 승인한다.
- 기존 EditMode 105/105, PlayMode 84/84가 유지된다.

## 구현자가 결정할 수 있는 세부 사항

- 정확한 폴리곤 수와 메시 분할 방식
- 공유 팔레트 재질의 셰이더 파라미터
- AI 아이콘의 최종 해상도와 압축 설정
- 애니메이션 상태 이름과 블렌드 시간
- 최종 폴리시 전에 사용할 임시 오디오
